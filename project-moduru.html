실시간 여행 일정 협업 웹 서비스

프로젝트 개요

여행 일정 동시 편집 서비스 MODURU를 개발하여 친구들과 실시간 장소 공유·투표· AI 추천 일정/동선 반영이 가능한 실시간 여행 일정 협업 플랫폼을 구축했습니다. WebSocket(STOMP+SockJS)·Redux 기반의 실시간 협업, Drag & Drop 편집, 지도 시각화, 리뷰·마이페이지 기능을 제공합니다.

  • 프로젝트명: MODURU (실시간 여행 일정 협업 서비스)
  • 기간: 2025.07.14 ~ 2025.08.18
  • 팀 구성: 6명 (프론트엔드 2, 백엔드 2, AI 1, 인프라 1)
  • 역할: 팀장, 프론트엔드

React 18 Redux Toolkit JavaScript Vite Axios WebSocket(STOMP+SockJS) CSS Tailwind CSS

  • AI 추천 활용성 증대: 일정·경로 추천 결과를 카드/보드에 매핑하여 즉시 편집 가능

도전 과제와 해결 과정

실시간 여행 일정 협업 서비스 MODURU에서 프론트엔드를 맡아 WebSocket 기반 일정 동시 편집 기능을 구현했습니다.

문제 1: WebSocket 끊김·재연결 이후 일정 변경이 화면에 반영되지 않는 경우

개발 과정에서 사용자들이 동시에 일정을 수정하는 상황에서 WebSocket 연결이 끊기거나 재연결되면, 일부 상황에서 다른 사용자의 일정 변경이 화면에 반영되지 않는 문제가 발생했습니다.

이를 단순한 렌더링 성능 저하가 아니라, WebSocket 재연결 이후 구독 복구와 메시지 발행 타이밍이 맞지 않아 동기화가 누락되는 구조적 문제로 판단했습니다. 연결이 끊긴 상태에서 발생한 변경 요청이 전송되지 못하거나, 재연결 이후 기존 구독 상태가 정상적으로 복원되지 않으면 사용자마다 서로 다른 일정 상태를 보게 될 가능성이 있다고 보았습니다.

  • 해결: 연결이 끊기면 기존 구독 정보를 정리해 불완전한 상태를 제거하고, 재연결이 이루어지면 모든 구독을 다시 설정하도록 구성해 동기화 누락 가능성을 줄였습니다. 연결이 복구되기 전에 발생한 발행 요청은 별도 큐에 저장해 두었다가, 재연결 이후 순차적으로 전송되도록 처리해 변경 사항이 유실되지 않도록 했습니다.

문제 2: Drag & Drop 연속 변경으로 전송·상태 갱신이 과도하게 누적되는 문제

장소 카드를 날짜별 일정 보드에 Drag & Drop으로 추가·이동·삭제하거나 같은 날짜 안에서 순서를 바꾸는 과정에서는 상태 변경이 짧은 시간 안에 반복적으로 발생하면서 전송 요청과 상태 갱신이 과도하게 누적되었습니다. 그 결과 화면 반응이 느려지고, 실시간 협업의 안정성이 떨어지는 문제가 나타났습니다.

특히 연속 편집 구간에서는 동일한 일정 변경이 지나치게 자주 전송되는 구조적 문제로 보았습니다.

  • 해결: 일정 동기화 발행을 제어하는 미들웨어를 설계하여, Drag & Drop 과정에서 같은 날짜에 대한 연속 변경은 짧은 시간 동안 하나의 요청으로 압축하도록 디바운스를 적용했습니다. 직전 발행 내용과 동일한 경우에는 재전송을 생략했고, WebSocket으로 수신된 메시지가 다시 로컬에서 재발행되지 않도록 처리해 동기화 루프도 차단했습니다.
  • 결과: 재연결 상황에서 일정 변경 반영의 안정성을 높일 수 있었고, 같은 날짜에 대해 10회 발생하던 발행 요청을 1회 수준으로 줄여 약 90%의 중복 트래픽 감소 효과를 확인했습니다.

문제 3: 일정/경로 추천 결과 UI 반영 어려움

  • 원인 분석: AI 서버 응답 데이터 구조가 복잡해 Redux 상태와 UI 간 매핑 과정에서 일관성 깨짐
  • 내 행동(해결 방법): aiScheduleSlice, aiRouteSlice를 직접 설계하여 추천 결과 구조화, 카드형 UI와 Drag & Drop 보드에 매핑되도록 컴포넌트 구현
  • 결과: AI 추천 일정을 즉시 확인·편집 가능해짐
